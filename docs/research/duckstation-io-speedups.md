# DuckStation emulated-I/O speedups

Researched 2026-10-26. The question: is there a way to speed up memory card reads and writes? Alongside that, which other DuckStation settings shorten emulated I/O waits (CD-ROM seeks, booting, disc loading), and which of them work in the per-game file Ludeum writes (`gamesettings/<Serial>.ini`, ADR 0021)?

All code citations are pinned to the installed build 12442 (`0.1-12442-gdd4a0eb77`, the `latest` tag). Nothing in these files changed between that build and `master` (build 12476) for the settings below. A build number is `git rev-list --count 0.1..<commit>`, which is what `git describe` prints after `0.1-`; I used it to date each setting.

## Answer

**Yes: `[MemoryCards] FastForwardAccess = true`** ("Fast Forward Memory Card Access", default off). It's a boolean and has been in DuckStation **since build 8639** (2025-02-15), so build 12442 has it. **It works per game.** The per-game layer reads every key, and Game Properties shows the checkbox on its Console page. **It doesn't shorten the emulated access.** The memory card keeps its real timing. Instead, each time a 128-byte sector is read or written, **DuckStation turns the speed limiter off (unlimited speed) until 30 frames after the last sector access.** So it's about as safe as pressing fast-forward yourself, and it doesn't taint save states. The cost is that menus which keep polling the card run unthrottled. **The game database turns it off for 18 entries** (trait `DisableFastForwardMemoryCardAccess`, build 9985 on): Broken Sword II, Dead in the Water, Lunar – Silver Star Story, Tales of Destiny, Twisted Metal 4 and Zoboomafoo, all because their "menu constantly accesses card". **No setting shortens memory card or pad/SIO bus timing itself.** Those delays are fixed constants in `pad.cpp`.

Two other speedups work per game in the same way and are worth having next to the existing `ReadSpeedup`:
- **`[CDROM] SeekSpeedup`** (same 0–6 encoding as `ReadSpeedup`: 1 off, 2–6 times, 0 Maximum). It speeds up CD seeks. It's riskier ("crash games which do not expect the CD-ROM to operate faster"), and the game database turns it off for 2 entries.
- **`[BIOS] PatchFastBoot`** with **`[BIOS] FastForwardBoot`**. These skip the BIOS logo, then run unthrottled until the game's first frame.

`[CDROM] LoadImageToRAM` (Preload Image to RAM) only removes *host* disk hitches. It doesn't speed up emulated I/O, and it refuses multi-disc playlists. That covers every Ludeum multi-disc Version.

## How the per-game layer applies these

- At boot, `System::UpdateGameSettingsLayer` loads `gamesettings/<serial>.ini` as the game layer (if `[Main] ApplyGameSettings`, default true, and the file isn't empty). `System::LoadSettings` then runs `g_settings.Load(si, …)` on the *layered* interface (game over base). Every key in `Settings::Load` can therefore be set per game. No list restricts which keys are allowed. https://github.com/stenzek/duckstation/blob/dd4a0eb779296a525f8b10b6d9a45911ad6d088f/src/core/system.cpp (~1051–1085, ~1495–1530)
- Order of overrides in `LoadSettings`: the ini (base, then game) → `ApplySettingRestrictions()` (Safe Mode, achievements hardcore) → game database `ApplySettings` (only if `[Main] ApplyCompatibilitySettings`, default true) → patch overrides → `FixIncompatibleSettings` (e.g. Fast Forward Boot needs Fast Boot). So **the game database wins over Ludeum's per-game file** for traits it sets. Same file, ~1073–1087; https://github.com/stenzek/duckstation/blob/dd4a0eb779296a525f8b10b6d9a45911ad6d088f/src/core/settings.cpp (~303–304, ~1220–1303)
- Game Properties (`SettingsWindow` in per-game mode) adds the BIOS, Console, Emulation and Memory Cards pages. It adds Debugging only when debug options are shown, and never Advanced or Game List. https://github.com/stenzek/duckstation/blob/dd4a0eb779296a525f8b10b6d9a45911ad6d088f/src/duckstation-qt/settingswindow.cpp (~98–200)
- Whether fast boot applies is decided after the game settings are loaded ("Are we fast booting? Must be checked after updating game settings."). system.cpp ~1814–1818

## Fast Forward Memory Card Access: `[MemoryCards] FastForwardAccess`

- **Key, type, default:** `memory_card_fast_forward_access = si.GetBoolValue(MEMORY_CARDS_SECTION_NAME, "FastForwardAccess", false)`, written back as a bool. `MEMORY_CARDS_SECTION_NAME` is `"MemoryCards"`. https://github.com/stenzek/duckstation/blob/dd4a0eb779296a525f8b10b6d9a45911ad6d088f/src/core/settings.cpp (~169, ~569, ~946); `bool memory_card_fast_forward_access : 1 = false` https://github.com/stenzek/duckstation/blob/dd4a0eb779296a525f8b10b6d9a45911ad6d088f/src/core/settings.h (~316)
- **UI (Qt):** a checkbox, "Fast Forward Memory Card Access", in the Console group of the **Console** page (not the Memory Cards page). Its help text: "Fast forwards through memory card access, both loading and saving. Can reduce waiting times in games that frequently access memory cards." Default "Unchecked". https://github.com/stenzek/duckstation/blob/dd4a0eb779296a525f8b10b6d9a45911ad6d088f/src/duckstation-qt/consolesettingswidget.cpp (~47–48, ~100–102); https://github.com/stenzek/duckstation/blob/dd4a0eb779296a525f8b10b6d9a45911ad6d088f/src/duckstation-qt/consolesettingswidget.ui (~64)
- **UI (Big Picture):** the same label and text under Console. It's drawn outside the `if (!game_settings)` blocks, so it appears in per-game settings too. https://github.com/stenzek/duckstation/blob/dd4a0eb779296a525f8b10b6d9a45911ad6d088f/src/core/fullscreenui_settings.cpp (~3395–3398)
- **Per game:** yes. The Console page is in Game Properties, and the widget is bound to the per-game settings interface like the others. When the game has the trait, the checkbox is made unavailable: `SetAvailability(m_ui.fastForwardMemoryCardAccess, !m_dialog->hasGameTrait(GameDatabase::Trait::DisableFastForwardMemoryCardAccess))`. consolesettingswidget.cpp ~155–156
- **Introduced:** build **8639**, commit e9bfca8 "System: Add 'Fast Forward Memory Card Access' option" (2025-02-15; "Does what it says on the tin."). It hasn't been renamed. https://github.com/stenzek/duckstation/commit/e9bfca8ccac43899866a12e19523944e1cd1864a
- **Mechanism:** `MemoryCard` calls `System::OnMemoryCardAccessed()` when it starts each sector, at `m_sector_offset == 0` in both `ReadData` and `WriteData`. https://github.com/stenzek/duckstation/blob/dd4a0eb779296a525f8b10b6d9a45911ad6d088f/src/core/memory_card.cpp (~180–186, ~215–222). That function returns early unless the setting is on. Otherwise it sets `memory_card_fast_forward_frames = MEMORY_CARD_FAST_FORWARD_FRAMES` (30) and, if the counter was 0, calls `UpdateSpeedLimiterState()`. system.cpp ~114, ~4102–4109
- While the counter is above 0, `target_speed = 0.0f`, which means the throttler is off and the emulator runs as fast as the host can, like Fast Forward Boot. `throttler_enabled = (target_speed != 0.0f)`. system.cpp ~3780–3790
- `FrameDone()` decrements the counter once per frame and restores normal speed when it reaches 0. This happens after the run-ahead replay early-return, so it counts presented frames, not replayed ones. system.cpp ~2178–2212. In practice: unthrottled from the first sector until about 30 frames (half a second) after the last one.
- **Emulated timing is unchanged.** The game still sees the real transfer delays, so this can't break game logic the way the CD speedups can. There's no setting for the memory card's or the SIO's own timing: `pad.cpp` hard-codes it ("ACK delay is between 6.8us-13.7us …", "Memory card responds faster, approximately 5us or ~170 ticks", `GetTransferTicks()`). The only settings `pad.cpp` reads are run-ahead and "load devices from save states". https://github.com/stenzek/duckstation/blob/dd4a0eb779296a525f8b10b6d9a45911ad6d088f/src/core/pad.cpp (~95–110, ~190–200, ~687)
- **Game database:** trait `DisableFastForwardMemoryCardAccess`, display name "Disable Fast Forward Memory Card Access". `ApplySettings` sets `memory_card_fast_forward_access = false` and shows "Fast forward memory card access disabled." https://github.com/stenzek/duckstation/blob/dd4a0eb779296a525f8b10b6d9a45911ad6d088f/src/core/game_database.cpp (~132, ~174, ~629–635). Added in build **9985** (c5d9358, 2025-10-29). https://github.com/stenzek/duckstation/commit/c5d93583daf8d5178fed4540b77b29ffe31ac5b4
  - **18 entries** in `gamedb.yaml`, all because a menu keeps reading the card: Broken Sword II (SCES-00798/00801/00802, SLUS-00812; "Load/save menu constantly accesses card, makes navigation very difficult"), Dead in the Water (SLUS-00693), Lunar – Silver Star Story / Complete (SCPS-45249/45250, SLUS-00628/00899, SLUS-90055; "Title screen constantly accesses card"), Tales of Destiny (SLPS-01100, previews and others), Twisted Metal 4 (and its demo), and Zoboomafoo – Leapin' Lemurs!. https://github.com/stenzek/duckstation/blob/dd4a0eb779296a525f8b10b6d9a45911ad6d088f/data/resources/gamedb.yaml (~20870–20937, ~36709, ~98849–98948, ~174789–174850, ~186744–186763, ~202892)
- **Safe Mode, hardcore, save states:** none of these touch it. Safe Mode (`[Main] DisableAllEnhancements`) and the achievements-hardcore block in `ApplySettingRestrictions` don't reset it, and hardcore only clamps `fast_forward_speed` to ≥1 or 0, where 0 is "unlimited" and stays allowed. settings.cpp ~1220–1300. It isn't a save-state taint (the taints are CPU Overclock, CD-ROM Read/Seek Speedup, Force Frame Timings, 8MB RAM, Cheats, Patches and Memory Card Mismatch). system.cpp ~452–462, ~5034–5052. The counter isn't serialized, so rewinding or loading a state neither starts nor stops it.
- **Side effects (from the code):** audio plays at `[Audio] FastForwardVolume` while it's unthrottled (`GetAudioOutputVolume`, system.cpp ~5620–5630). Frame pacing and host sync drop out, because they need the throttler. The host-side `.mcd` file is still written 5 s after the last change (`SAVE_DELAY_IN_SECONDS = 5`). https://github.com/stenzek/duckstation/blob/dd4a0eb779296a525f8b10b6d9a45911ad6d088f/src/core/memory_card.h (~49)

## CD-ROM Seek Speedup: `[CDROM] SeekSpeedup`

- **Key, type, default:** `GetSaturatedIntValue<u8>(CDROM_SECTION_NAME, "SeekSpeedup", 1)`, so the ini is read as any u8. settings.cpp ~514, ~903. The UI offers values `{1, 2, 3, 4, 5, 6, 0}`, labelled "None (Normal Speed)", "2x" … "6x", "Maximum (Safer)". consolesettingswidget.cpp ~19, ~82–83; consolesettingswidget.ui ~230–271
- **UI:** Qt "Seek Speedup:" on the Console page, CD-ROM Emulation group. Help: "CD-ROM Seek Speedup", default "None (Normal Speed)": "Reduces the simulated time for the CD-ROM sled to move to different areas of the disc. Can improve loading times, but crash games which do not expect the CD-ROM to operate faster." consolesettingswidget.cpp ~126–129. Big Picture "Seek Speedup": "Speeds up CD-ROM seeks by the specified factor. May improve loading speeds in some games, and break others." fullscreenui_settings.cpp ~3445–3448
- **Per game:** yes, on the same Console page. Made unavailable when the game has `DisableCDROMSeekSpeedup`. consolesettingswidget.cpp ~163–165
- **Introduced:** build **4070**, 98e4c18 "CDROM: Add seek speedup enhancement" (2021-05-23). 0 was "Instant" until build 8338 (561397a, 2025-01-09: "'Instant' seek is now renamed to Maximum as well"). Build 9949 (7517813, 2025-10-20) dropped the UI choices above 6× ("In the majority of games it just crashes. Maximum is safer."), but `Load` still accepts any u8. https://github.com/stenzek/duckstation/commit/98e4c181ca3f98633b2d94f536aee900c2ea5372, https://github.com/stenzek/duckstation/commit/561397a53cbae0567229337cbc215b17091a8e8d, https://github.com/stenzek/duckstation/commit/751781325c0fab788776c074ee8f0440fef6ffa5
- **Mechanism:** this one does shorten emulated timing. `GetTicksForSeek` divides the computed seek time by the factor, down to a minimum of `MIN_SEEK_TICKS`. At 0 it returns `MaxSeekSpeedupCycles` (default 30000 cycles, about 0.9 ms) for every seek. https://github.com/stenzek/duckstation/blob/dd4a0eb779296a525f8b10b6d9a45911ad6d088f/src/core/cdrom.cpp (~1664–1667, ~1736–1745)
- **Game database:** `DisableCDROMSeekSpeedup` forces it to 1 ("CD-ROM seek speedup disabled."), in build 9021 and later (a6b59f9). Two entries, both Arcade Party Pak ("Fixes Rampage and 720 freeze upon loading."). `cdromMaxSeekSpeedupCycles` overrides the Maximum delay for 4 entries, and only when the setting is 0. game_database.cpp ~534–538, ~645–651; gamedb.yaml ~8940, ~8968
- **Caveats:** values 2–6 set the "CD-ROM Seek Speedup" save-state taint, which warns "may be unstable" when such a state is loaded without the setting on. 0 doesn't set it (`> 1`). system.cpp ~5034–5042, ~5054–5080. At start-up DuckStation shows "CD-ROM read/seek speedup is enabled. This may crash games." unless a trait has already turned it off. system.cpp ~5176–5180. Safe Mode resets it to 1. settings.cpp ~1222–1253. Hardcore leaves it alone.

## CD-ROM Read Speedup: `[CDROM] ReadSpeedup` (already in Ludeum)

- `GetSaturatedIntValue<u8>(…, "ReadSpeedup", 1)`. UI values `{1,2,3,4,5,6,0}`: "None (Double Speed)", "2x (Quad Speed)" … "6x (12x Speed)", "Maximum (Safer)". settings.cpp ~513; consolesettingswidget.ui ~184–222. Help: "Speeds up CD-ROM reads by the specified factor. Only applies to double-speed reads, and is ignored when audio is playing. May improve loading speeds in some games, at the cost of breaking others." consolesettingswidget.cpp ~122–125
- It applies only when `CanUseReadSpeedup()`: double speed, no CDDA, no XA, and (with `DisableSpeedupOnMDEC`) MDEC idle. At 0, once a sector's data has arrived, the read completes within `MaxReadSpeedupCycles`. cdrom.cpp ~1546–1552, ~1606–1612, ~4000–4012
- Build 1923 (8ba93b3, 2020-10-05). Maximum since 8338. Gamedb `DisableCDROMReadSpeedup` covers 15 entries (build 9021). `cdromMaxReadSpeedupCycles` covers 263 entries (build 8836), and only when the setting is 0. game_database.cpp ~540–545, ~637–643. Taints, the warning and Safe Mode behave as for seek speedup.

## Fast Boot and Fast Forward Boot: `[BIOS] PatchFastBoot`, `[BIOS] FastForwardBoot`

- **Keys:** `PatchFastBoot` (bool, default `DEFAULT_FAST_BOOT_VALUE = false`) and `FastForwardBoot` (bool, default false), both in `[BIOS]`. settings.cpp ~533–534, ~924–925; settings.h ~326–327, ~660
- **UI:** Qt checkboxes "Fast Boot" ("Skips the boot animation. Safe to enable.") and "Fast Forward Boot" ("Fast forwards through the early loading process when fast booting, saving time. Results may vary between games."), on the **Console** page. Fast Forward Boot is greyed out unless Fast Boot is on. consolesettingswidget.cpp ~41–44, ~95–99, ~170–177. Big Picture labels: "Enable Fast Boot" ("Patches the BIOS to skip the boot animation. Safe to enable.") and "Fast Forward Boot". fullscreenui_settings.cpp ~3386–3394
- **Per game:** yes, on the Console page. Both are made unavailable when the game has `ForceFullBoot`. consolesettingswidget.cpp ~151–153
- **Introduced:** `PatchFastBoot` in a4749238 (2019-11-16, "System: Add 'fast boot' option (skip boot logo)"), which is before the `0.1` tag, so it has no build number. `FastForwardBoot` in build **7625** (29da7f7, 2024-09-26). https://github.com/stenzek/duckstation/commit/a47492382c65529b60623bb099930b7268987808, https://github.com/stenzek/duckstation/commit/29da7f7211c0ae07ffce95d13bef8cd60a888bf0
- **Mechanism:** fast boot patches the BIOS to skip the logo. Fast forward boot sets `target_speed = 0` (unthrottled) while `internal_frame_number == 0` in fast-boot mode, i.e. until the game presents its first frame. `FixIncompatibleSettings` forces it off without fast boot. system.cpp ~1814–1818, ~3780–3790, ~5614–5618; settings.cpp ~1302
- **Game database:** `ForceFullBoot` ("Fast boot disabled.") covers 10 entries: The Adventures of Lomax / Lomax ("Stops crashing after FMV.") and Nightmare Creatures ("Full boot improves reliability."). Since build 7807 (5bca12a). game_database.cpp ~613–619; gamedb.yaml ~3778, ~97700–97738, ~120807–120911
- **Caveats:** Safe Mode turns fast boot off. Neither is a save-state taint, and hardcore doesn't restrict either. A Game that boots its disc through the BIOS is the only case either applies to (not EXE/PSF boots). system.cpp ~1578–1583

## Preload Image to RAM: `[CDROM] LoadImageToRAM`

- Bool, default false. settings.cpp ~509, ~898. Qt label "Preload Image to RAM": "Loads the game image into RAM. Useful for network paths that may become unreliable during gameplay. In some cases also eliminates stutter when games initiate audio track playback." consolesettingswidget.cpp ~60–61, ~130–133. Big Picture "Preload Images to RAM". fullscreenui_settings.cpp ~3450–3453. Per game: yes, on the Console page. The README lists it as "Preloading of disc images to RAM to avoid disk sleeping hitches." https://github.com/stenzek/duckstation/blob/dd4a0eb779296a525f8b10b6d9a45911ad6d088f/README.md (~40)
- Build **1300** (9496c99, 2020-07-22). https://github.com/stenzek/duckstation/commit/9496c992f7da5bb8644c91d0f093a4f6ab239e5a
- **Mechanism:** `CDROM::PrecacheMedia()` runs at boot, on disc insert and on state load. It has the image precache itself (CHD decompresses into memory) or copies it into a memory image. **It refuses images with more than one sub-image** ("CD image preloading not available for multi-disc image"), and an `.m3u` playlist is one of those. So it does nothing for Ludeum's multi-disc Versions. https://github.com/stenzek/duckstation/blob/dd4a0eb779296a525f8b10b6d9a45911ad6d088f/src/core/cdrom.cpp (~1066–1091), https://github.com/stenzek/duckstation/blob/dd4a0eb779296a525f8b10b6d9a45911ad6d088f/src/core/cdrom_async_reader.cpp (~145–180); system.cpp ~1915, ~3122, ~4237
- **Emulated timing is unchanged.** It only removes host read stalls. The default `[CDROM] ReadaheadSectors = 8` already reads ahead on a worker thread ("Reduces hitches in emulation by reading/decompressing CD data asynchronously on a worker thread."). fullscreenui_settings.cpp ~6246–6250

## Debugging-page CD tunables

- `[CDROM] MaxReadSpeedupCycles` and `MaxSeekSpeedupCycles` (u32, clamped to ≥1, default 30000; "Sets the minimum delay for the 'Maximum' read/seek speedup level"), and `[CDROM] DisableSpeedupOnMDEC` ("Tries to detect FMVs and disable read speedup during games that don't use XA streaming audio."). They're on the Qt Debugging page as "tweak options" and in Big Picture's advanced section. settings.cpp ~515–519, ~904–913; https://github.com/stenzek/duckstation/blob/dd4a0eb779296a525f8b10b6d9a45911ad6d088f/src/duckstation-qt/debuggingsettingswidget.cpp (~236–244); fullscreenui_settings.cpp ~6252–6265
- The game layer reads them like any other key, but Game Properties shows them only when DuckStation's debug options are on. The two cycle keys were one key, `MaxSpeedupCycles`, from build 8344 (40589dc) until build 8835 (d2c09df, "Split read and seek cycles for maximum CD speedup"). `DisableSpeedupOnMDEC` dates from build 9372 (b6b1a5e). https://github.com/stenzek/duckstation/commit/d2c09dfaff23bca528bcd0bcccf576ee35f19170, https://github.com/stenzek/duckstation/commit/b6b1a5e33cef099721804f31349e774c6d626055
- These tune or limit the existing speedups rather than adding a new one. The game database already sets them per game (263 read-cycle overrides, 4 seek-cycle overrides, 85 `DisableCDROMSpeedupOnMDEC`), so Ludeum shouldn't write them.

## Not found / unverified

- No setting for pad or SIO bus speed or for memory card transfer timing exists in `settings.cpp`. The timing is hard-coded in `pad.cpp` and `memory_card.cpp`. Searched; none found.
- I didn't run DuckStation, so the real-world effect (how much time Fast Forward Memory Card Access saves in a given game) is **unverified**. So is the "about half a second" figure, which assumes 30 frames at 60 Hz.
- DuckStation has no official wiki in the repo, and I found no release notes beyond commit messages. Each "since build" figure comes from the first commit that adds the key to `settings.cpp` (`git log -S`), converted with `git describe`.
