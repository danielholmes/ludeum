# A PlayStation Game's memory card lives in the Data folder, where DuckStation is pointed at it

Superseded by [0024](0024-ludeum-installs-duckstation-and-says-where-it-keeps-things.md): DuckStation names its cards, and only their directory is Ludeum's to say.

I want each PlayStation Game's memory card, its Game save, listed on Game detail with the Card saves in it, and kept in the Data folder so Dropbox has it. DuckStation keeps cards in its own `memcards` folder, by default one per game named by its title in DuckStation's game database (`Resident Evil - Director's Cut (USA)_1.mcd`), the two discs of a disc set sharing one. As with save states ([0022](0022-duckstation-save-states-stay-its-own-and-are-backed-up.md)), the folder is set only in its own `settings.ini` (`[MemoryCards] Directory`, read from the base layer alone). But unlike save states, a card can be put anywhere for one game: the per-game file Ludeum writes on every Play ([0021](0021-duckstation-settings-go-in-its-per-game-file-named-by-the-discs-serial.md)) honours `[MemoryCards] Card1Type = Shared` with `Card1Path` an absolute path, as DuckStation's own Game Properties sets it.

So every PlayStation Play points the ROM's card 1 at `Emulators/DuckStation/Memory Cards/<Serial>.mcd` in the Data folder, named by Disc 1's Serial and written into every Disc's per-game file, so a multi-disc ROM keeps one card whatever disc is in. That card is the only copy: nothing is copied, there's no backup to keep in step and nothing to Restore, and Dropbox has each save a few seconds after the game makes it, as DuckStation writes the card whole under another name and renames it into place. It changes DuckStation only for that game, as 0021's settings already do, and DuckStation opened on its own uses the same card. The card is per ROM, not per Game, as a disc reads only saves of its own region and Serial; a Serial never changes where a ROM's name can.

We considered copying, as save states are: leaving the card in `memcards` under DuckStation's name and backing it up into the Data folder. That keeps DuckStation's memory card editor listing every card, but it takes the same copying and timing as save states for a file DuckStation can simply be told to keep elsewhere, two copies to reconcile, and Ludeum working out DuckStation's name for every card, with its disc sets, custom titles and disc-specific exceptions.

## Consequences

- A ROM's existing card is copied in at its first Play, when the Data folder hasn't got one: the card DuckStation's own settings give it (by default its title in the bundled `discdb.yaml`, or its disc set's in `discsets.yaml`, or its file's name for a disc DuckStation doesn't know). DuckStation's copy stays where it was, unused. A title the game was given in DuckStation's game list isn't looked for. Until then, Game detail shows DuckStation's card, saying it isn't in the Data folder yet.
- Every PlayStation ROM needs Disc 1's Serial to be Played: one with none, or whose Serials haven't been read yet, is refused, rather than Played with a card outside the Data folder.
- Card 2 is left as DuckStation has it (off, by default), and card 1's type and path set in DuckStation's Game Properties are put back at the next Play.
- The card isn't in DuckStation's memory card editor's list, which shows only its own folder; it can still be opened there by its path.
- Ludeum never deletes a card, even when its ROM is Deleted or relinked to a dump with another Serial: it stays in the Data folder, listed nowhere, until the ROM comes back.
- While the Data folder is missing, DuckStation can't read or write the card.
