# An Automatic Match needs the checksum and the name to agree

A checksum lookup through Hasheous is not trusted on its own. A dry run of the first Import against my library found that about 2% of checksum matches pointed at the wrong IGDB game: sequels and spin-offs linked to the original (*Super Star Wars: Return of the Jedi* → *Super Star Wars*, *Battletoads & Double Dragon* → *Battletoads*), and some linked to bundles. So a ROM is only linked automatically when its checksum identifies an IGDB game *and* its name matches that game's name or one of its alternative names, after normalising. Anything else goes to the Review queue as a suggestion. That keeps our assumption that Matches don't need correcting afterwards, at the cost of about 50 extra one-click confirmations.

**Amended 2026-09-27:** this ADR first also said a ROM is never linked to an IGDB bundle. Measuring the rules against the same library ([`prototype/matching-rules`](https://github.com/danielholmes/games-journal/tree/prototype/matching-rules)) showed that IGDB types single-cartridge collections such as *Super Mario Advance 2* and *Kirby Super Star* as Bundles, so the ban would leave those ROMs with no IGDB link at all. The name rule already keeps out the wrong multi-game packs, so a Bundle is now matched like any other game. "Names agree" means equality after normalising, never a prefix or containment test, because nearly every wrong checksum match was the IGDB name being a prefix of the ROM's title.
