# LaunchBox is the only source of Box art

Supersedes the libretro-thumbnails parts of [0006](0006-box-art-before-igdb-cover-art.md), [0013](0013-box-art-for-games-with-no-rom.md) and [0018](0018-launchbox-box-art-after-libretros.md).

A Game's Box art now comes only from the LaunchBox Games Database: the Cover is my upload, else LaunchBox's box, else the first Bundle's Cover, else IGDB's Cover art. libretro-thumbnails is gone, along with its Screenshots. While both were shown side by side on Game detail, LaunchBox's box was as good as libretro's or better in nearly every Game I looked at (about 60; I preferred libretro's once), often a sharper scan, and IGDB's and LaunchBox's Screenshots between them were always at least as good as libretro's title screen and snap. Matched across the whole journal, the two picked a different game for 5 of the 1,264 Games both had a box for. Once LaunchBox looked in MS-DOS for PC Games and picked the game released closest to IGDB's year, 3 were left, and in none was LaunchBox's pick wrong on its own: libretro's box for Command & Conquer: Renegade was a 1986 game's, found through IGDB's alternative name. Dropping libretro loses 7 boxes LaunchBox doesn't have (Super Famicom Wars, Duke Nukem's second and third episodes, Captain Comic, Castlevania: The Adventure ReBirth, a HeroQuest prototype and World Championship Rugby); an upload fixes any I mind.

libretro matched a ROM by its file name, which also gave it the ROM's region. LaunchBox matches by the Game's names, so before libretro could go its box had to be for the Regions of the Game's ROMs (0018's amendments), and a ROM whose name has no region tag had to take its Regions from Hasheous ([0019](0019-a-rom-with-no-region-tag-takes-its-regions-from-hasheous.md)). A Game with ROMs now finds its box by its names as a Game with none does: 0013's rule that a Game's ROMs decide its Box art, even when none of them has any, goes, and so does choosing which of its ROMs' boxes it shows. IGDB's alternative names are now tried for every Game, not only ones with no ROM.

Nothing about Box art is kept in the journal any more: each ROM's libretro names and whether it had been looked up are dropped (`v38`), the Import has no Box art step, and renaming a Game, changing its IGDB link or Matching a ROM no longer sends its ROMs to be looked up again. A Game's Box art is worked out each time its Cover is shown, from the dump in the cache, so any of those changes it with no step to rerun. libretro's listings and the images downloaded from it, about 470 MB, are deleted from the cache. GitHub's rate limit, which libretro's listings shared with everything on the connection, no longer applies.

One source can fail where two backed each other up. A dump that can't be downloaded or read is an alert, and the last one read stays in use (0018's amendment). A Game LaunchBox has no box for, or that it matches wrongly, shows IGDB's Cover art or the wrong box until I upload one, as a wrong libretro match did.

We considered keeping libretro after LaunchBox, for the 7 boxes only it has. That would have kept its per-ROM journal columns, the Import step that fills them, the lookups after a rename or relink, two title-matching paths and GitHub's rate limit, all for 7 Covers an upload can fix. We considered keeping it first, as its match by file name is the more certain one. That hid every LaunchBox match on the 97% of Games libretro found, and the comparison showed LaunchBox matching as well once it had the ROMs' Regions.
