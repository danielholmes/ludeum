# Ludeum installs PCSX2 and says where it keeps things

Amends [0021](0021-duckstation-settings-go-in-its-per-game-file-named-by-the-discs-serial.md) and [0025](0025-a-playstation-roms-serials-say-its-regions-before-hasheous.md) (a PlayStation 2 ROM's Serials are read too, and say its Regions as a PlayStation ROM's do).

I want PCSX2's Save states and memory cards in the Data folder's `Emulators/`, as DuckStation's (0024), MesenCE's (0027) and ares's (0028) are, and the PCSX2 Ludeum plays with to be Ludeum's own. The research is [pcsx2-under-ludeums-management.md](../research/pcsx2-under-ludeums-management.md). PCSX2 fits more closely than MesenCE or ares did, and nearly as DuckStation does:

- **A `portable.txt` beside `PCSX2.app` makes its folder the data root.** PCSX2's program folder on macOS is the one holding the bundle, so the marker goes beside the app, as ares's `settings.bml` does, and nothing inside the notarised bundle changes. Without it the root is `~/Library/Application Support/PCSX2`.
- **Every folder it keeps is a key in `inis/PCSX2.ini`**, under `[Folders]`, taking an absolute path and read from that base file only; a per-game file can't move one. PCSX2 keeps its settings in memory and rewrites the whole file, atomically, a second after any change.
- **Its Save states and memory cards are keyed by the disc, not the file.** A state is `<serial> (<CRC>).<nn>.p2s`, the serial from the disc's `SYSTEM.CNF` (its `BOOT2` line) and the CRC from the boot program, with a PNG screenshot inside; so a Game's states follow its ROM through Rename, Archive and a change of image form, and there's nothing for Ludeum to move. A state's format version has held since v2.7.200 (March 2026) after three bumps in the nine months before.
- **A folder memory card is a card per game.** A directory at a card's name is a folder card, one subfolder per save named as the game named it, with the disc's serial in the name, and PCSX2 shows a running game only the saves whose names carry its serial (or the serials its game database says share saves). A file card holds every game's saves in one 8 MB file.
- **Every nightly is a versioned tag** with a SHA-256 digest per asset, and nothing ages off. The macOS tar holds a Developer ID–signed, notarised app, built x86_64, which this Mac runs under Rosetta 2.
- **A Play can start from a state** with `-statefile`, and `-batch` quits PCSX2 when the game closes.

Two things are different. There was no PCSX2 data on this Mac at all (it had never run here, and no PlayStation 2 BIOS was found), so there's nothing to move over, but a first run is PCSX2's own setup, which Ludeum's seeded settings file would skip. And today's Play passed `-gamecfg` with a file of Ludeum's, which replaced PCSX2's own per-game file outright and caught any change made in its Game Properties in a file the next Play overwrote.

So:

- **Ludeum installs PCSX2.** Install in the Emulators sheet, a Background task, fetches `pcsx2-v2.9.103-macos-Qt.tar.xz` for the pinned tag (`v2.9.103`, a nightly, the version the launch code was written against) from `PCSX2/pcsx2`, checks it against the SHA-256 pinned in code, unpacks it with `tar`, confirms its version with `-version` (which prints and exits before PCSX2 touches its settings or data root) and puts it in `Emulators/PCSX2/PCSX2.app` in the Ludeum folder with an empty `portable.txt` beside it. PCSX2 is no longer looked up by bundle ID, and any other version is a wrong build to install again. A bump is the version and digest in code; a bump past a state format change costs the Save states, as ares's does, and is rare and deliberate.
- **Standing settings** are written into `Emulators/PCSX2/inis/PCSX2.ini` before every Play and after Install, changing only Ludeum's keys:
  - `[Folders]`: `Savestates`, `MemoryCards`, `Bios`, `GameSettings`, `InputProfiles`, `Snapshots`, `Cheats`, `Patches` and `Textures` as `Data/Emulators/PCSX2/Save States`, `Memory Cards`, `BIOS`, `Game Settings`, `Input Profiles`, `Screenshots`, `Cheats`, `Patches` and `Textures`. Its caches, covers and logs stay in the root beside the app, as they're rebuildable.
  - `[AutoUpdater] CheckAtStartup` off: the updater would replace the bundle under a new name. No launch that boots a game checks anyway.
  - `[EmuCore] EnableFastBoot` on, in place of `-fastboot`, and `SaveStateOnShutdown` on, so a Game has a Resume state, as DuckStation's does.
  - `[EmuCore/GS] VsyncQueueSize = 0`, the lowest input latency PCSX2 has (its Optimal Frame Pacing), the one key the `-gamecfg` file carried. It's the same for every Game, so it's global.
  - `[UI] SettingsVersion = 1`, which PCSX2 checks for and resets the file without.
- **A file PCSX2 hasn't made yet is seeded with its own first-run defaults.** PCSX2 writes its keyboard controls for controller 1 and its hotkeys only when it makes the file itself, and defaults everything else in code; a file Ludeum seeds skips that and its setup wizard. So the seed carries those two sections as PCSX2's source at the pinned build writes them (`Pad::SetDefaultControllerConfig`, `Pad::SetDefaultHotkeyConfig`), and nothing else. A controller is mapped in PCSX2's own settings during a Play, as every Emulator's own settings are.
- **Play is refused until there's a BIOS.** PCSX2 can't boot without a PlayStation 2 BIOS, which Ludeum can't supply. Play is refused with where to put one (`Data/Emulators/PCSX2/BIOS`) while that folder has no file; PCSX2 takes the first file there that is one, so none is named in its settings. Play is also refused while any PCSX2 is open, as for DuckStation and ares: PCSX2 would write its settings over Ludeum's, and nothing stops a second copy opening.
- **`-gamecfg` goes.** A Play is `-batch [-statefile <state>] -- <rom>`. A PlayStation 2 Game's own settings are PCSX2's, set in its Game Properties and kept in its per-game files in the Data folder's `Game Settings`, which Ludeum doesn't write, as 0029 made DuckStation's.
- **PCSX2 names and manages memory cards; Ludeum only says where, and makes the first two folder cards.** Before a Play, each of PCSX2's two default card names (`Mcd001.ps2`, `Mcd002.ps2`) that has nothing at it in `Memory Cards` is made as an empty directory, so PCSX2 opens it as a folder card and the game formats it at first use, as it would a new card. A card already there, folder or file, is left alone. Nothing names a card in a Game's settings.
- **Serials are read off PlayStation 2 discs too**, as PlayStation ones are (0021): the `BOOT2` line's executable, named as PCSX2 names it, read at the next Import or by Add ROM, from the ROM folder or streamed out of its `.7z`. By 0025 they say a ROM's Regions before Hasheous when its name has no region tag.
- **Game detail** lists a PlayStation 2 Game's Save states by its ROMs' Serials, by Disc, then Resume, then slot, each slot's previous one after it, each with the screenshot in it and when it was saved, to Play from or delete. It also lists its Card saves: on every folder card, the subfolders whose names carry one of its Serials, or one PCSX2's game database (`GameIndex.yaml`, `memcardFilters`) lists with it, each with the title the game wrote into its `icon.sys`, in plain characters, and when it was last written. A file card isn't read. There's no backup, restore or delete of a Game save, as for the other Emulators.
- **The PlayStation 2 ROM folder no longer reads `.cue` as ready.** PCSX2 opens no cue sheet (`.iso`, `.chd`, `.cso`, `.zso`, `.gz`, `.bin`, `.mdf`); a `.bin` opens on its own.

## Considered Options

- **Keep `-gamecfg`** with Ludeum's file as the game layer: rejected. It hides every per-game fix or input profile set in Game Properties, and catches changes in a file the next Play overwrites; 0029 moved DuckStation off the same model.
- **Pin the stable channel** (v2.8.2, two months old, the same state format): rejected for now. v2.9.103 is what the launch code was checked against and what this Mac has; both are immutable tags with digests, so the pin can move to a stable tag at any bump.
- **Let PCSX2 write its first file and run its setup wizard** at the first Play, with the Standing settings applied from the second: rejected. The first Play's states and cards would land in the root beside the app and need moving, and the wizard's BIOS page has nothing to pick until a BIOS is in the Data folder, which Ludeum's refusal says more plainly.
- **Seed the file and flag PCSX2's setup wizard** (`SetupWizardIncomplete`) for its BIOS and controller pages: rejected. The hotkeys would still be missing, and a cancelled wizard quits PCSX2 with the game unplayed.
- **File cards, with Ludeum reading the PlayStation 2 card file system** to list a Game's Card saves: rejected. A folder card is a card per game already, Dropbox syncs one save's files rather than an 8 MB card on every write, and its saves are a directory listing.
- **A card per Game by `[MemoryCards] Slot1_Filename` in the per-game file**, as 0023 did for DuckStation: rejected, as 0024 rejected it. Game saves are the Emulator's concern; Ludeum shows them.
- **Ludeum works out a disc's CRC as well as its serial**, so a state's full name is known: rejected. Only `-state <n>` needs it, and `-statefile` takes any file; listing by `<serial> (` finds every state of a Game, another dump's included.
- **ARMSX2**, the native Apple Silicon fork, instead of PCSX2 under Rosetta 2: not for now. Its macOS builds are nightlies only, their signing is unverified, and it's a young fork; it keeps PCSX2's layout and flags, so a swap later is a new root, not a conversion.
- **Format the folder cards in Ludeum** by writing PCSX2's superblock file: rejected. The game formats an unformatted card at first use, as it does a new file card of PCSX2's own making, and a superblock written by Ludeum would be a format PCSX2 never checked.
- **Warn before a bump that changes the state format**, or keep the old build: rejected, as 0028 did, as tooling for a rare event. The commit that bumps it is tagged `[SAVEVERSION+]`, which a bump can check by hand.

## Consequences

- Nothing moves over: no PCSX2 data existed on this Mac. `/Applications/PCSX2.app` and Ludeum's `PCSX2 game settings.ini` in the Ludeum folder are mine to delete, and a PlayStation 2 BIOS is mine to put in `Data/Emulators/PCSX2/BIOS`.
- A new Mac downloads PCSX2 once, from the Emulators sheet, and needs Rosetta 2 and a BIOS in the Data folder.
- The next Import reads every PlayStation 2 ROM's Serials, streaming the start of each `.7z`'s image through 7-Zip as it does PlayStation's, so Game detail can list its states and saves.
- PCSX2 writes its settings and per-game files under a temporary name and renames them into place, but writes states and cards in place, so a crash mid-write can leave half a file; a state's `.backup` holds the slot's previous state. One Mac writes the Data folder at a time, as 0024 says, and the PCSX2 folders are marked available offline in Dropbox, as PCSX2 reads with plain file calls.
- The first time a game saves to a card, it asks to format it, as on a new console.
