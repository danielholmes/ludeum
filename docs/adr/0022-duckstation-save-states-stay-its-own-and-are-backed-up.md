# DuckStation's save states stay its own, and are backed up into the Data folder

Superseded by [0024](0024-ludeum-installs-duckstation-and-says-where-it-keeps-things.md): the states live in the Data folder, with nothing copied.

I save, load and delete save states in DuckStation's own menus, and want to go on doing so with no rules to remember, and to keep DuckStation usable on its own. But I also want each PlayStation Game's states listed in Ludeum, to Play from one, to delete one, and to have them backed up with the Data folder (#81).

DuckStation keeps a game's states in one folder, `savestates` in its data folder, as `<serial>_<slot>.sav` (slots 1 to 10), `<serial>_resume.sav` (saved on closing the game, `SaveStateOnExit`) and, for the one a slot held before it was saved over, `<serial>_<slot>.bak` (`CreateSaveStateBackups`). The folder is set only in its own `settings.ini` (`[Folders] SaveStates`): it reads folders from that base layer alone (`System::UpdateFolderPaths`, build 12442), so the per-game file Ludeum writes ([0021](0021-duckstation-settings-go-in-its-per-game-file-named-by-the-discs-serial.md)) can't move them. Pointing the folder (or a link in its place) into the Data folder would change DuckStation for every game, inside Ludeum or not, which its own settings are kept clear of. Linking each state file in doesn't work either: DuckStation writes a state under another name and renames it into place, replacing the link.

So the states stay where DuckStation keeps them, and Ludeum copies them: into `Emulators/DuckStation/Save States/` in the Data folder, flat and under the same names. A Serial never changes where a Game's name or a ROM's match can, and a copy can be put back by copying it, with or without Ludeum. Only the states of a Game's ROMs' Serials are copied; another game's, and the global slots (`savestate_<slot>.sav`), are left alone. The copy is written under a hidden name and renamed into place, keeping when the state was saved, so Dropbox never uploads half of one. They're backed up when Ludeum opens and each time it becomes active again (back from DuckStation), and while it's open a second after DuckStation's folder last changed; nothing is while the Data folder is missing.

We considered lending the states to DuckStation for each Play: keeping them only in the Data folder, copying a Game's into DuckStation's folder before it's Played and taking them back after. That keeps DuckStation's folder empty of anything Ludeum has, but DuckStation's menus would show only what was lent, a state saved outside Ludeum would be taken over at the Game's next Play, and a Play that ended with Ludeum closed would leave them stranded. Backing up keeps DuckStation exactly as it is.

A backup is never deleted because DuckStation's copy is gone: a fresh DuckStation, a new Mac, or a backup made while its folder was empty would otherwise take every backup with it. Such a state shows as not in DuckStation, to Restore (copy it back) or delete; Play from it opens the backup. Deleting a state in Ludeum sends both copies to the Trash.

## Consequences

- Game detail lists a PlayStation Game's states by Disc, then Resume, then slot, each with its screenshot and when it was saved (its file's modification date, as DuckStation shows it). States have no names. The screenshot is read from the state's header, which DuckStation compresses with Zstandard by default, so it needs `zstd` (`brew install zstd`), now one of the optional system tools; Deflate and XZ ones need nothing.
- Play from a state is `-statefile <state> -- <rom>`, with the exact file rather than `-state <slot>`, as a multi-disc game's state is filed under the Disc that was running. A ROM renamed since the state was saved is booted in its place, with DuckStation's warning that this may be unstable.
- A state deleted in DuckStation stays in the backup until it's deleted in Ludeum, and saving over a slot replaces its backup: the `.bak` is the only history.
- A Game whose Serials haven't been read shows no save states, and its states aren't backed up until they are.
- Memory cards are left as they are. (Later, a PlayStation Game's card was put in the Data folder instead, which a per-game file can do: [0023](0023-a-playstation-games-memory-card-lives-in-the-data-folder.md).)
