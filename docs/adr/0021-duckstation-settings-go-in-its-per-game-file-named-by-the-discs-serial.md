# DuckStation settings go in its per-game file, named by the disc's Serial

Amends [0008](0008-journal-owns-per-game-emulator-settings.md) for DuckStation: its Play no longer passes every setting, defaults included, for that launch only.

A PlayStation Play passed DuckStation `-settings <file>`, a copy of its own `settings.ini` with the Game's run-ahead (and later its CD read speedup) written in, so nothing carried over between Games and DuckStation's own settings were never touched. DuckStation dropped `-settings` (and `-portable`) in build 8843, in April 2025 (`ffd6726a`, "Qt: Drop -settings/-portable CLI parameters"): it hadn't been tested in years, was broken for a long time with nobody complaining, and an alternative `settings.ini` makes little sense when the rest of what DuckStation keeps (play time, custom properties, crash dumps) stays in its data folder anyway. Every build Ludeum has accepted is later than that, so every PlayStation Play failed with "Unknown parameter: -settings". Nothing has replaced it: DuckStation's command line takes no settings at all, and its repository has no issues or discussions where one might be asked for.

What DuckStation does have is per-game settings: `gamesettings/<serial>.ini` in its data folder, layered over `settings.ini`, which is where its Game Properties saves them. The serial is the disc's, as DuckStation reads it: the executable its `SYSTEM.CNF` boots, `cdrom:\SLUS_005.51;1` becoming `SLUS-00551`. So a Play now merges the Game's settings into that file, and opens the ROM with nothing else on the command line. Ludeum's settings win where both have one: one the Game has is set, and one it hasn't is taken out, even if it was set in DuckStation, so DuckStation's own applies and what Ludeum shows is what's played. That's a change for run-ahead, which DuckStation got as 0 when a Game had none; now it's DuckStation's own, and the CD read speedup already was. Every other setting in the file stays, and so does anything changed in DuckStation during the Play, which the copy lost. A multi-disc Version's file is Disc 1's, as DuckStation's is, unless that keeps each Disc apart (`UseSeparateConfigForDiscSet`), when each Disc's is written too.

Writing the file needs the disc's Serial, so each ROM now has its **Serials**, one per Disc, read off the Discs once at an Import (`v40`), and by Add ROM. Reading them off the disc is what DuckStation itself does, so the file's name always matches, and it gave a Serial for every one of my 113 PlayStation ROMs, 112 of them in a `.7z`, streamed out of it with nothing written to disk: about 9 minutes for all of them. 7-Zip packs an archive's cue sheets and playlists after its images, so reading one unpacks every Disc first; an archived ROM's Discs and data tracks are found by their names instead where they say (`(Disc 2)`, `(Track 1)`), and only what the disc's layout needs is unpacked, though that can be most of it (Resident Evil – Director's Cut's `SYSTEM.CNF` is 660 MB in). Nothing else had them: Hasheous, LaunchBox and IGDB have no serials; Redump's serial DAT covers 108 of the 113 by checksum but has no stated licence; DuckStation's own disc database is CC BY-NC-ND. A Disc DuckStation names by a hash (no `SYSTEM.CNF`, `PSX.EXE`) has no Serial, which Ludeum doesn't work out. The Serials also say exactly which version a ROM is, and its region for certain ([0019](0019-a-rom-with-no-region-tag-takes-its-regions-from-hasheous.md)), for matching against sources that have them later; they aren't used for matching yet.

## Consequences

- A Game with DuckStation settings of its own can't be Played until its Serial is read, so it's refused until the next Import after `v40` reads it, and for good if its Disc 1 has none or it's a `.chd` or `.pbp`, which aren't read yet: setting them back to Default plays it. A Game with none of its own plays regardless. To revisit if it gets in the way.
- DuckStation's per-game files now hold Ludeum's settings: changing run-ahead in DuckStation's Game Properties lasts only until the next Play from Ludeum.
- The first Import after `v40` reads every PlayStation ROM's Discs: about 9 minutes for my 113, once, during which the background refresh waits. A ROM kept online only by Dropbox is left until it's downloaded.
- The `-settings` copy in the Ludeum folder is deleted at the next PlayStation Play.
- Later, every Play also writes fast boot into the file (`[BIOS] PatchFastBoot` and `FastForwardBoot`), not a setting of the Game's own, so a Game with none of its own still gets a file. DuckStation has `-fastboot`, but it overrides the game database's `ForceFullBoot` for the games fast boot breaks, and fast-forwarding the boot has no flag, so the file is the one place for both. A Disc 1 with no Serial boots in full.
